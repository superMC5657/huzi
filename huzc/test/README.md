# Huzc 测试目录

回归入口是 `test.sh`：编译并运行每个用例，断言退出码和标准输出。交互式示例（`10_guess_number_game`）跳过。

## 目录

| 目录 | 内容 |
|------|------|
| `cases/` | 正例：63 个 `.hz` 示例，全部要编译通过且输出正确 |
| `expected/` | 每个正例对应的标准输出快照（`.stdout`），逐字节比对 |
| `neg/` | 负例：必须失败的用例 |
| `out/` | 编译产物输出目录（自动生成，不提交） |
| `pkg/` | 包管理器的测试工程（见下） |
| `bench_compare.py` / `bench_baseline.txt` | 性能门禁脚本与历史比值存档 |

## 负例命名

- `*.compile_fail.hz`：编译期必须报错（如类型不匹配、未知函数、Trait 缺方法）
- `*.runtime_fail.hz`：编译通过、运行期必须失败（如除零、数组越界、RC 循环泄漏、`panic`）

## `pkg/` 子工程

包管理器的测试夹具，由 `crates/huzc/src/pkg/` 的 Rust 单测调用，不经过 `test.sh`：

| 工程 | 测什么 |
|------|--------|
| `app/` | 最简场景：单个本地依赖 `my_math 1.0.0`，含落盘的 `vendor/` 样板 |
| `app_multi/` | 版本求解：`^1.0.0` 在 `1.0.0` / `1.2.0` 中选最高满足版 `1.2.0` |
| `app_diamond/` | 冲突报错：左右两条依赖分别要求 `shared` 的 `1.0.0` 与 `2.0.0`，无共同版本直接失败 |
| `fixtures/` | 假包仓库：`my_math`（单版本）、`my_math_multi`（多版本）、`diamond`（菱形依赖的左右包与共享包） |
