# RFC: 泛型函数实参类型推导 (Generic Type Inference)

## 1. 目标与设计动机
在 Huzi 初始泛型实现 (P4) 中，调用泛型函数必须书写显式类型实参，例如 `id<i32>(42)`。
本 RFC 规范泛型函数调用点的实参类型自动推导规则：
- 支持 `id(42)` 自动推导为 `id<i32>(42)`；
- 保持单态化机制与名称修饰 (Name Mangling) 完全不变；
- 当推导失败（歧义冲突、缺乏必要形参）时，产生友好的编译诊断并提示显式写法。

## 2. 语法与作用范围
### IN
- 函数调用点省略类型实参：`f(x, y)` 替代 `f<T1, T2>(x, y)`。
- 支持标量字面量（`i32`, `f64`, `str`, `char`, `bool`）、变量、结构体、`Box<T>`、`vec<T>`、数组、元组的类型推导。
- 多形参共同推导同一类型变量：校验一致性。
- 推导结果直接填入 AST 的 `CallExpr.type_args`，复用单态化管线。

### OUT
- 结构体字面量实例化仍需显式标注（如 `Pair<i32, str> { ... }`）。
- 不支持 Hindley-Milner 全局双向类型推导。
- 不支持特化与 where 约束。

## 3. 推导算法规范
设泛型函数模板声明为 `fn F<T1, ..., Tn>(p1: P1, ..., pm: Pm)`，实参为 `(a1, ..., am)`：
1. **实参类型推导**：
   - 标量字面量：`42` -> `i32`, `3.14` -> `f64`, `"s"` -> `str`, `'c'` -> `char`, `true` -> `bool`。
   - 变量标识符：根据当前局部作用域推导类型。
   - 复合表达式：根据结构体定义、Box 嵌套、Vec 元素递归推导。
2. **形参实参统一 (Unification)**：
   - 若形参 `Pi` 为类型变量 `Tk`，且实参类型为 `Ak`：
     - 若 `Tk` 尚未绑定，则记录 `Tk = Ak`。
     - 若 `Tk` 已绑定为 `Ak'`，若 `Ak != Ak'`，则报错：`Type inference conflict for 'Tk': deduced both 'Ak'' and 'Ak'`。
   - 若形参 `Pi` 为复合类型（如 `Box<U>`），实参类型亦为复合类型（如 `Box<V>`），递归统一内部类型。
3. **完全性检查**：
   - 检查每一个 `T1..Tn` 是否均已绑定。
   - 若存在未绑定的类型变量 `Tj`（如无对应形参），则报错：
     `Cannot infer type argument 'Tj' for generic function 'F', please specify explicitly with F<...>(...)`。
4. **单态化执行**：
   - 将推导得到的完整类型实参赋值给调用节点的 `type_args`。
   - 后续完全沿用既有单态化缓存与特化编译。
